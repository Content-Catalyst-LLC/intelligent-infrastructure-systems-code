# Engineering Notes

## Design priorities

1. Define service purpose, public-interest goals, critical users, and governance responsibilities before choosing platforms.
2. Treat digital infrastructure as layered: physical connectivity, network, compute, storage, interoperability, identity, trust, security, continuity, and governance.
3. Measure reliable and affordable access, not only nominal coverage.
4. Test cloud and data infrastructure for portability, region dependency, backup, recovery, and degraded-mode operation.
5. Preserve interoperability evidence: API catalogs, schemas, registries, exchange agreements, and integration tests.
6. Secure identity, trust, credentials, certificates, logs, edge nodes, cloud platforms, APIs, backups, and operational interfaces.
7. Assess vendor concentration, procurement leverage, portability, and exit strategies.
8. Evaluate inclusion across geography, cost, disability, language, device access, documentation, and assisted-service availability.

## Common failure modes

- digital infrastructure is reduced to broadband coverage alone
- cloud dependency is mistaken for resilience
- APIs exist without durable standards or governance agreements
- identity systems exclude users without alternatives or appeals
- service continuity is assumed without tested failover and recovery
- digital-first services remove non-digital access before access barriers are solved
- vendor concentration creates strategic fragility
