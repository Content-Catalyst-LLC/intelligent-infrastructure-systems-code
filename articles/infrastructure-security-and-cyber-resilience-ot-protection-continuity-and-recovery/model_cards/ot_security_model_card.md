# OT Security Model Card

## Intended use

- document OT zones, conduits, remote access, segmentation status, and operational recovery concerns
- support cyber-physical scenario review
- connect security findings to process stability and public-service continuity

## Not intended for

- replacing operational engineering analysis
- publishing sensitive network diagrams
- treating OT systems like ordinary enterprise IT assets

## Required caveats

- OT controls must account for safety, timing, process integrity, and downtime constraints
- patching and scanning require operational coordination
- service continuity must be validated through exercises
