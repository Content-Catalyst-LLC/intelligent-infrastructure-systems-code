# Digital Twin Infrastructure Intelligence Framework

| Layer | Question | Evidence artifact |
|---|---|---|
| Physical system | What physical assets, networks, environments, and service boundaries are represented? | Scope statement, asset registry, network map |
| Data acquisition | Which sensors, inspections, operational records, geospatial layers, and environmental data feed the twin? | Telemetry source registry and data catalog |
| Digital state | How is the current estimated infrastructure state represented? | Digital twin state table |
| Model logic | Which models estimate behavior, simulate futures, or compare interventions? | Model registry and model cards |
| Scenario logic | Which stressors, interventions, assumptions, and time horizons are tested? | Scenario manifest |
| Simulation outputs | What performance, cost, risk, service, or resilience outcomes are produced? | Simulation output table |
| Validation | How are model outputs tested against observed outcomes or expert review? | Validation and sensitivity log |
| Decision support | How do outputs influence maintenance, operations, planning, or governance? | Decision and intervention log |
| Public accountability | Can users understand scope, assumptions, uncertainty, and limits? | Public evidence package |
