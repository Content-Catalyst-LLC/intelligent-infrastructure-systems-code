# Model Validation Note

Digital twins should not be trusted simply because they are visually compelling or computationally sophisticated.

A validation package should document:

- physical system boundary
- model type and version
- data sources and timestamps
- calibration or estimation method
- benchmark cases
- backtesting results where available
- expert review where available
- sensitivity analysis
- uncertainty ranges
- known failure modes
- valid-use limits
- governance owner

The twin should be treated as decision support, not decision authority.
